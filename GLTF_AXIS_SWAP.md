# GLTF axis-remapping migration

## Current behavior

Current RecoilEngine versions convert GLTF/GLB node transforms and geometry into
the engine model coordinate frame while loading the model. A BOS script therefore
uses the same piece axes when attached to equivalent S3O and GLTF models.

Compile these scripts normally:

```sh
python bos2cob_py3.py myunit.bos
```

Do not remap `turn`, `move`, `spin`, wait, or scale axes based on the model file
format. COB's existing legacy X-move and Z-turn sign conventions remain unchanged
and are already accounted for by established S3O animation exporters.

## Deprecated controls

The following controls no longer change generated bytecode:

- `--gltf-swap`
- `--gltf-swap-s3o`
- `#define GLTF`
- `#define GLTF <custom-axis-spec>`

The compiler accepts these temporarily and prints a warning so old build commands
and source files can be found and cleaned up. Silently continuing to remap axes
would double-convert animations after the engine-side fix.

## Migration

1. Remove `--gltf-swap` and `--gltf-swap-s3o` from compiler invocations.
2. Remove GLTF axis specifications from BOS source files and included headers.
3. Recompile the BOS without model-format-specific options.
4. Verify the same compiled COB against equivalent S3O and GLTF/GLB models.

For models produced from the established S3O Blender workflow, retain
`s3ocompat=true` in the GLTF scene extras or adjacent model metadata. The option
selects the source model's facing convention; it no longer changes the coordinate
space in which BOS animation commands execute.

Older RecoilEngine releases that still place the GLTF coordinate transform on a
synthetic root piece are not compatible with this compiler behavior. Use matching
engine and toolchain versions during migration.
